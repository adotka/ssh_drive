# SSH Drive

Программа для Windows, которая подключает папку SSH-сервера **как обычный диск**
(`Z:`, `Y:` и т. д.) в Проводнике. Есть графический интерфейс, вход по ключу
(с установкой ключа на сервер) и вход по паролю.

```
Windows Explorer  →  Z:  →  rclone (SFTP)  →  ваш SSH-сервер
```

* GUI — **tkinter**: входит в Python, ничего дополнительно ставить не нужно.
* Движок монтирования — **rclone** (скачивается автоматически, ~30 МБ).
* Драйвер диска — **WinFsp** (устанавливается один раз, нужны права администратора).
* Иконка в системном трее — **pystray** (ставится вместе с зависимостями).

---

## Быстрый старт

**Установщик (рекомендуется):**

1. Запустите `SSHDrive-1.0.0-x64.msi` (лежит в `dist/` и в релизе на GitHub).
   Установка пользовательская, без UAC: `%LOCALAPPDATA%\Programs\SSH Drive`.
2. Ярлыки появятся в меню «Пуск» (папка **SSH Drive**) и на рабочем столе.
3. Установщик добавляет **автозапуск**: ярлык в «Автозагрузке» с ключом
   `--tray`. При входе в Windows окно не открывается — программа работает в
   трее и поднимает диски.
4. Если WinFsp ещё не установлен, программа предложит его поставить (UAC).

**Портативный exe:** `dist\SSHDrive.exe` (24 МБ) или
`SSHDrive-offline.exe` (53 МБ, всё внутри). Автозапуск включается в меню
«Сервис → Запускать при входе в Windows».

**Дальше (любой вариант):**

1. Нажмите **Добавить**, заполните сервер, пользователя и способ входа.
2. **Подключить** — диск появится в «Этот компьютер».
3. Крестик окна **сворачивает программу в трей**, диски продолжают работать.
   Полный выход — правый клик по иконке → «Выход» (или «Файл → Выход»).
4. При следующем запуске подключённые диски поднимаются автоматически
   (если пароль/парольная фраза ключа сохранены).

Если установлен Python, можно запускать из исходников: `run.bat`.

## Готовые сборки

| Файл | Размер | Что это |
|---|---|---|
| `SSHDrive-1.0.0-x64.msi` | ~46 МБ | установщик: меню «Пуск», ярлык на рабочем столе, автозапуск, внутри rclone и MSI WinFsp |
| `SSHDrive.exe` | ~24 МБ | портативный: rclone и WinFsp скачиваются при первом запуске |
| `SSHDrive-offline.exe` | ~53 МБ | портативный offline: rclone.exe и установщик WinFsp внутри |

* Установщик ставит программу **для текущего пользователя** (без UAC) и
  регистрируется в «Параметры → Приложения». Удаление убирает ярлыки,
  автозапуск и файлы программы; профили в `%APPDATA%\SSHDrive` остаются.
* Портативные exe работают из любой папки, Python не нужен.
* WinFsp — драйвер, его нужно установить один раз (UAC). В MSI и offline-exe
  установщик WinFsp лежит рядом, так что интернет не обязателен.
* Файлы не подписаны сертификатом, SmartScreen может предупредить:
  «Подробнее» → «Выполнить в любом случае».
* Автозапуск можно выключить: «Сервис → Запускать при входе в Windows»
  (ярлык в `shell:startup`).

Собрать заново:

```bat
build_exe.bat
```

Нужен Python 3.10+ (лучше 3.13) и интернет на время сборки. Скрипт создаёт
`.venv-build`, `build/` и `dist/`.

## Вход по ключу (рекомендуется)

1. В профиле выберите «по ключу» → **Создать…** (или укажите существующий
   приватный ключ, например `id_ed25519`).
2. Сохраните профиль и нажмите **Установить ключ**. Программа:
   * сначала попробует войти по ключу (если он уже стоит — ничего не спросит),
   * иначе подключится к серверу **по паролю** (пароль спросит один раз),
   * добавит публичный ключ в `~/.ssh/authorized_keys` (без дублей),
   * сразу проверит вход уже по ключу.
3. Дальше пароль не нужен — при подключении используется ключ.

Ключи создаются в `%APPDATA%\SSHDrive\keys\` в формате OpenSSH (ed25519).
Парольную фразу можно задать при создании ключа; она хранится зашифрованной.
Если ключ зашифрован, на время подключения создаётся его расшифрованная копия
в `%LOCALAPPDATA%\SSHDrive\tmp` (rclone не умеет читать зашифрованные ключи
нового формата); при отключении копия удаляется.

На сервере должны быть разрешены ключи (`PubkeyAuthentication yes`) и каталог
`.ssh` с правами `700`, файл `authorized_keys` — `600` (программа выставляет это
сама при установке).

### Если на сервере Windows OpenSSH

Для пользователей из группы «Администраторы» Windows OpenSSH читает не
`%USERPROFILE%\.ssh\authorized_keys`, а
`C:\ProgramData\ssh\administrators_authorized_keys`. Программа пытается записать
туда тоже, если SSH-сессия запущена с правами администратора. Иначе добавьте
ключ вручную или используйте обычного (не административного) пользователя.

## Вход по паролю

В профиле выберите «по паролю». Пароль спрашивается при подключении; галочка
«Сохранить пароль» записывает его в `profiles.json` **в зашифрованном виде**
(Windows DPAPI: расшифровать может только этот пользователь на этой машине).

Пароль передаётся в rclone через переменные окружения процесса, в файлы
в открытом виде не пишется.

## Возможности

| Что | Где |
|---|---|
| Несколько профилей серверов | главное окно |
| Буква диска: вручную или «авто» | профиль → «Буква диска» |
| Стартовая папка на сервере (`/home/user`, `C:/Users/user`) | профиль → «Папка на сервере» |
| Режим только чтение | профиль → «Только чтение» |
| Дополнительные флаги rclone | профиль → «Доп. опции rclone» |
| Проверка входа без монтирования | кнопка «Проверить вход» |
| Автоподключение дисков при запуске | профиль → «Подключать при запуске программы» |
| Автозапуск при входе в Windows | «Сервис → Запускать при входе в Windows» |
| Список доверенных ключей хостов, удаление | Сервис → «Известные хосты…» |
| Журнал подключений и ошибок | внизу окна + `%LOCALAPPDATA%\SSHDrive\logs\app.log` |

### Автоподключение при запуске

* После успешного подключения профиль запоминается: при следующем запуске
  программы его диск поднимется сам, по возможности на той же букве
  (`last_drive` в профиле).
* Явное «Отключить» (или «Отключить все диски» в трее) снимает автоподключение —
  этот диск больше не будет подниматься само.
* «Выход» с активными дисками автоподключение **не** снимает: в следующий раз
  они подключатся снова.
* Если для входа нужен пароль, а он не сохранён, или ключ зашифрован, а
  парольная фраза не сохранена, автоподключение такого профиля пропускается
  (причина пишется в журнал, в состоянии профиля — «нужен пароль»).
  Включите «Сохранить пароль» в профиле, чтобы диск поднимался сам.
* Галочка **«Подключать при запуске программы»** в профиле позволяет выключить
  или снова включить автоподключение вручную.

### Проверка ключа сервера

При первом подключении показывается отпечаток ключа хоста (SHA256) и вопрос
«доверять?». Ключ сохраняется в `%APPDATA%\SSHDrive\known_hosts`, при следующих
подключениях сверяется автоматически. Если ключ сервера изменился —
подключение блокируется, пока вы не удалите запись в «Известные хосты».

Проверенный ключ передаётся движку rclone как *пин* (`host_keys`): тот же
алгоритм и те же байты ключа, что проверил paramiko. Это важно, потому что
paramiko и rclone по-разному выбирают тип ключа (ed25519/rsa) при согласовании;
без пина rclone мог отказать с `knownhosts: key mismatch` при полностью
правильном ключе. Пиннинг работает в rclone 1.75+ (его скачивает программа);
для более старых сборок используется обычный known_hosts.

## Трей и завершение работы

* Крестик окна **не завершает** программу: окно скрывается, иконка остаётся
  рядом с часами, диски продолжают работать.
* Двойной клик по иконке или пункт «Открыть окно» возвращает окно.
* Меню иконки: «Открыть окно», «Отключить все диски», «Выход».
* «Файл → Выход» и «Выход» в трее — настоящий выход: программа спросит про
  активные диски, отмонтирует их и завершится.
* **Автозапуск**: MSI создаёт ярлык в «Автозагрузке» с ключом `--tray`, поэтому
  при входе в Windows окно не открывается — программа сразу в трее и поднимает
  диски. Включить/выключить можно в «Сервис → Запускать при входе в Windows»
  (ярлык в `shell:startup`). Удаление программы убирает этот ярлык.
* Второй экземпляр не запускается (чтобы не было двух окон и конфликтов за
  буквы дисков) — вместо этого появится подсказка про иконку в трее.
* Отключить трей для отладки: `set SSHDRIVE_NO_TRAY=1` перед запуском.

## Если что-то не работает

**«WinFsp не найден»** — Сервис → «Установить WinFsp» (нужен интернет и
подтверждение UAC); после установки программа подхватит драйвер сразу. Без
интернета скачайте MSI с <https://winfsp.dev/rel/>, установите вручную и нажмите
«Сервис → Проверить окружение».

**«rclone не найден»** — Сервис → «Скачать / обновить rclone».
Можно указать свой `rclone.exe` через переменную `SSHDRIVE_RCLONE`.

**Диск не появляется** — посмотрите журнал: там вывод rclone. Частые причины:
неверный пароль/ключ, закрыт порт 22 (или другой), сервер не разрешает SFTP
подсистему, буква диска уже занята.

**«Сервер отклонил вход»** — проверьте логин; для root обычно запрещён вход по
паролю (`PermitRootLogin`); ключ мог не попасть в `authorized_keys`.

**`rclone: handshake failed: knownhosts: key mismatch`** — rclone и paramiko
выбрали разные типы ключа одного и того же сервера (типично для ed25519/rsa).
Начиная с этой версии проверенный ключ передаётся rclone как пин, так что
ошибка не должна появляться. Если она есть: обновите rclone («Сервис → Скачать /
обновить rclone»), перезапустите программу; в крайнем случае удалите запись
хоста в «Сервис → Известные хосты» и подключитесь заново, подтвердив ключ.

**Диск «отвалился»** — пропала сеть или сервер закрыл сессию. Нажмите
«Отключить», затем «Подключить».

**Антивирус ругается на rclone** — это известная официальная утилита; можно
добавить в исключения или скачать вручную с <https://rclone.org/downloads/> и
положить как `%LOCALAPPDATA%\SSHDrive\bin\rclone.exe`.

## Ручной запуск (для разработки)

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m sshdrive
```

Полезные параметры:

* `python -m sshdrive --smoke` — открыть окно и закрыть через пару секунд
  (быстрая проверка, что всё импортируется и рисуется);
* `set SSHDRIVE_DEBUG=1` — печатать в журнал полные трассировки ошибок;
* `set SSHDRIVE_RCLONE=D:\tools\rclone.exe` — использовать свой rclone;
* `set SSHDRIVE_INSTANCE=test` — запустить второй экземпляр рядом с рабочим (отладка);
* `set SSHDRIVE_NO_PROMPTS=1` — не предлагать установку rclone/WinFsp при старте.

Структура проекта:

```
run.bat              запуск из исходников (venv + зависимости)
run_app.py           точка входа для PyInstaller
build_exe.bat        сборка dist\SSHDrive.exe и SSHDrive-offline.exe
sshdrive.spec        спецификация PyInstaller
installer/           исходник MSI (WiX)
tools/               иконка, WiX, rclone/WinFsp для offline-сборки
requirements.txt     paramiko, cryptography, pystray, pillow
sshdrive/app.py      окно, профили, подключение
sshdrive/tray.py     иконка в трее (pystray)
sshdrive/autostart.py  ярлык в «Автозагрузке»
sshdrive/dialogs.py  диалоги профиля и пароля
sshdrive/sshutil.py  SSH: вход, known_hosts, установка ключа
sshdrive/rclone.py   скачивание rclone, mount/unmount
sshdrive/keys.py     генерация ключей ed25519
sshdrive/profiles.py профили, автоподключение
sshdrive/winfsp.py   проверка и установка WinFsp
sshdrive/secretstore.py  DPAPI-шифрование паролей
```

## Ограничения

* Windows 10/11 x64; нужен установленный драйвер WinFsp.
* Это сетевой диск, а не локальный: скорость ограничена SSH-каналом, а при
  обрыве связи диск пропадает (данные в кэше rclone дописываются при
  восстановлении соединения).
* Не стоит использовать для баз данных и «живых» файлов, которые постоянно
  переписываются с нескольких машин.
* Кэш rclone (`--vfs-cache-mode writes`) складывает незаписанные файлы в
  `%LOCALAPPDATA%\rclone\vfs`; принудительно отключать программу во время
  записи большого файла не нужно.

## Удаление

1. Отключите все диски в программе.
2. Закройте её и удалите папки `%APPDATA%\SSHDrive`, `%LOCALAPPDATA%\SSHDrive`
   и каталог проекта вместе с `.venv`.
3. WinFsp (если больше не нужен) удаляется через «Параметры → Приложения».
